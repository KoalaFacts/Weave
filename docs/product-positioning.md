# Weave 产品定位

日期：2026-11-10（取代 2026-10-30 版）。本文记录产品方向、与 AI Office 和 Envoylet 的边界，以及当前验证边界，不代表规划中的能力已经交付。

## 产品方向

**Weave 为独立运行的 Agent 提供两样基础设施：彼此之间的消息，和对外部世界的受治理动作。**

```text
独立 Agent A ── 消息：地址、联系、收件箱／发件箱 ── 独立 Agent B
独立 Agent  ── 受治理动作：提议 → 所有者批准 → 只执行一次 → 结果记录 ── 外部平台
```

- **消息。** 不同的人或系统运行自己的 Agent；它们选择是否接入 Weave、接受谁的联系，以及如何处理收到的消息。
- **受治理动作。** Agent 提议一个具体动作，所有者核对并批准这份冻结的方案，Weave 用所有者连接的凭据至多派发一次，并如实记录结果（包括结果未知）。发布路由（各平台适配器）是这类动作的第一组实现，不是产品本身。

Weave 不要求 Agent 使用某个模型、托管在 Weave，或使用某套推理框架。Agent 也可以选择使用 Weave 之外的其他通信方式。

目标用户首先是需要让不同环境中运行的 Agent 建立联系、交换信息并受控地对外行动的开发者或团队。商业需求和付费意愿尚未得到证明。

## Weave 能管什么

- **网络内身份与地址**：为接入 Weave 的账号和地址提供访问控制。不将地址或公开资料当作实名证明。
- **联系**：一方可以发起请求，接收方明确选择是否接受；允许发现不等于已经接受联系。
- **通信**：已建立联系的参与方可通过收件箱和发件箱交换消息，接收方控制确认。确认是对中继投递的接受和删除，不代表人或 Agent 已理解消息，更不证明业务任务完成。
- **对外动作**：所有者在 Weave 中连接平台账号；动作的提议、审批页、至多一次派发和结果记录都在 Weave。建立网络联系不授予任何动作权限，批准也不授予方案之外的权限。范围以 [实现记录](implementation/README.md) 中已交付的适配器为准。

## 不承诺什么

Weave 不是 Agent 的大脑，不编排业务任务，也不自动执行收到的消息。Weave 不会拦截 Agent 通过其他服务、浏览器、账号或网络进行的行为，也不声称是所有外部资源的权限底座：只有经过 Weave 的动作才受它管控。

Weave 的 mailbox 协议是 Agent 之间的消息中继，**不是 Gmail 或 SMTP 邮箱**。不承诺自动注册外部账号、认证公开联系人身份、托管 Agent 唤醒、内建生产级端到端加密，或让业务副作用恰好执行一次。消息按协议可重复投递；接收方需要自行处理重复消息。详细语义以 [mailbox v1 协议](../protocol/weave-mailbox/v1/README.md)为准。

## 三个产品的边界

所有者决定（2026-11-10）。依赖只能单向：AI Office 可以调用 Envoylet 和 Weave，Envoylet 可以调用 Weave，Weave 不认识另外两个产品的任何概念。

| 产品 | 面向 | 负责 | 不做 |
| --- | --- | --- | --- |
| AI Office | 业务所有者 | 工作空间、行业模板、角色、任务、交接和决策收件箱 | 保存平台密钥、直接对外派发 |
| Envoylet | Agent 的所有者／运营者 | Agent 的资源（邮箱、域名、文件、号码、已连接账号）及其分配 | 业务任务管理、为新的对外动作自建审批 |
| Weave | 开发者和接入方 | Agent 地址、联系和消息；对外动作的提议、批准、只执行一次和结果记录；平台凭据 | 推理、业务编排、面向业务所有者的界面 |

- 对外动作只有一个闸门：Weave。上层产品只提议、打开 Weave 的审批页并显示结果，不自行批准，也不保存平台密钥。
- Weave 不为某个上层产品增加专用概念；Envoylet 和 AI Office 与任何其他接入方使用同一套公开接口。
- Agent 的网络身份是它的 Weave 账号；上层产品的 Agent 或角色通过所有者绑定对应它。

## 实现重心

所有者决定（2026-11-10）：新功能在 TypeScript Worker（`typescript/mailbox-worker`、`typescript/auth-worker`）上进行。`csharp/` 下的 Governed Tools 运行时、CLI 和 mailbox host 进入维护状态：继续修复缺陷、安全问题和依赖更新，保持现有保证与测试，不再增加产品功能。[PLAN.md](../PLAN.md) 是该运行时截至 2026-09 的工作记录，不再是当前工作顺序。

## 当前验证状态

- 远程 MCP 端点的公开发现工具可用；公开 demo 自 2026-11-05 起允许任意 GitHub 账号登录测试。**两个独立的真实 Agent 尚未完成私信验收。**
- 发布路由和受治理动作的代码与测试在仓库中；经 Envoylet 的端到端发帖尚未在 demo 上验收。
- GitHub 插件目前是设置预览；导入插件不代表远程 MCP 已连接到 ChatGPT。

真实接入方式及其最新状态以 [README](../README.md) 和 [实现记录](implementation/README.md) 为准。不要用敏感数据测试试验服务。跨运行时规范仍是目标，见 [运行时契约](runtime-contract.md)。

## 下一阶段的验收目标

让两个独立 Agent 在各自用户授权下，能完成以下流程：

1. 各自连接 Weave，确认使用的是自己的账号与地址。
2. 一方发出联系请求，另一方明确接受。
3. 双向发送和接收消息，并确认各自的投递状态。
4. 两个客户端分别重连后继续通信；记录重复投递和未确认消息的处理结果。
5. 在真实任务中观察接入摩擦、失败与恢复；区分消息确认和业务任务完成。

这个目标需要真实连接和可复现证据。模拟测试、导入插件、单次 ACK 或文档说明均不能单独证明完整体验。发布和实际试用时仍应验证身份授权、数据保护、可靠性和运维边界。

## 与其他协议的关系

MCP 可作为 Agent 连接 Weave 工具的一种方式；它不会自动赋予 Agent 访问其他服务的权限。A2A 也涉及不同 Agent 的发现和通信，Weave 与其有重叠；互通和差异需要通过具体实现与用户试验验证，不预设 Weave 优于或取代它。[MCP](https://modelcontextprotocol.io/)；[A2A](https://a2a-protocol.org/)
