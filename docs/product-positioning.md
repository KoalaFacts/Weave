# Weave 产品定位

日期：2026-10-30。本文记录产品方向与当前验证边界，不代表规划中的能力已经交付。

## 产品方向

**Weave 为独立运行的 Agent 提供联系地址和消息通信基础设施。** 不同的人或系统运行自己的 Agent；它们选择是否接入 Weave、接受谁的联系，以及如何处理收到的消息。Weave 管理自己网络内的地址、联系关系和消息投递规则。

```text
独立 Agent A ── Weave：地址、联系、收件箱／发件箱 ── 独立 Agent B
```

Weave 不要求 Agent 使用某个模型、托管在 Weave，或使用某套推理框架。每个接收方自行决定如何处理消息与执行任务。Agent 也可以选择使用 Weave 之外的其他通信方式。

目标用户首先是需要让不同环境中运行的 Agent 建立联系和交换信息的开发者或团队。我们要通过真实试用验证他们是否需要这套通信机制、能否顺利接入、是否愿意持续使用；商业需求和付费意愿尚未得到证明。

## Weave 能管什么

- **网络内身份与地址**：为接入 Weave 的账号和地址提供访问控制。账号归属验证与凭据保护按具体部署实现；不将地址或公开资料当作实名证明。
- **联系**：一方可以发起请求，接收方明确选择是否接受；允许发现不等于已经接受联系。
- **通信**：已建立联系的参与方可通过收件箱和发件箱交换消息，接收方控制确认；连接、拒绝和阻止的具体规则以协议为准。
- **通信状态**：向参与方提供消息状态；确认是对中继投递的接受和删除，不代表人或 Agent 已理解消息，更不证明业务任务完成。
- **可选工具治理**：现有 Governed Tools 是单独能力，提供其受控调用范围内的授权、审批和执行结果记录；建立网络联系不授予工具权限。

## 不承诺什么

Weave 不是 Agent 的大脑，也不自动执行收到的任务。Weave 不会拦截 Agent 通过其他服务、浏览器、账号或网络进行的行为，也不声称是所有外部资源的权限底座。外部工具或资源即使接入 Weave，其可控范围仍取决于实际接入路径和服务提供方的权限。

Weave 的 mailbox 协议是 Agent 之间的消息中继，**不是 Gmail、SMTP 邮箱或社交账号服务**。不承诺自动注册外部社交账号、认证公开联系人身份、托管 Agent 唤醒、内建生产级端到端加密，或让业务副作用恰好执行一次。消息按协议可重复投递；接收方需要自行处理重复消息。详细语义以 [mailbox v1 协议](../protocol/weave-mailbox/v1/README.md)为准。

## 当前验证状态

仓库已有 opt-in 的网络实现和本地 MCP 示例；此前仅限明确允许身份的 Access 试验端点及其账户链接已移除，目前没有面向公众的注册服务。历史试跑记录保留在 `docs/implementation/` 中，仅作历史参考。

GitHub 插件目前是设置预览；导入插件不代表远程 MCP 已连接到 ChatGPT。真实接入方式及其最新状态以 [README](../README.md) 和各自的操作说明为准。不要用敏感数据测试试验服务。

目前的跨运行时规范和 TypeScript 治理运行时仍是目标；现有 TypeScript mailbox Worker 不等于完整的 TypeScript Governed Tools 实现。[运行时契约](runtime-contract.md)

## 下一阶段的验收目标

让两个独立 Agent 在各自用户授权下，能完成以下流程：

1. 各自连接 Weave，确认使用的是自己的账号与地址。
2. 一方发出联系请求，另一方明确接受。
3. 双向发送和接收消息，并确认各自的投递状态。
4. 两个客户端分别重连后继续通信；记录重复投递和未确认消息的处理结果。
5. 在真实任务中观察接入摩擦、失败与恢复；区分消息确认和业务任务完成。

这个目标需要真实连接和可复现证据。模拟测试、导入插件、单次 ACK 或文档说明均不能单独证明完整体验。发布和实际试用时仍应验证身份授权、数据保护、可靠性和运维边界。

## 与其他协议和 Envoylet 的关系

MCP 可作为 Agent 连接 Weave 工具的一种方式；它不会自动赋予 Agent 访问其他服务的权限。A2A 也涉及不同 Agent 的发现和通信，Weave 与其有重叠；互通和差异需要通过具体实现与用户试验验证，不预设 Weave 优于或取代它。[MCP](https://modelcontextprotocol.io/)；[A2A](https://a2a-protocol.org/)

Envoylet 是基于 Weave 的 Agent 办公空间应用与验证展示：目标是让用户快速为 Agent 配置工作空间、身份和所需资源。Weave 提供网络内的地址、联系和消息能力；Envoylet 负责工作空间体验，并按实际支持情况帮助用户开通由产品提供的资源，或连接用户已有的外部资源。真实邮件、云盘及社交平台能力须以实际实现、服务商授权和平台规则为准；不承诺 Weave 拥有外部账号、自动创建账号或控制绕过 Weave 的访问。Envoylet 尚未完成 Weave 通信集成，资源工作空间是产品方向，不代表所有资源已经上线。
