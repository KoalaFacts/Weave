# Model-driven Weave pair acceptance

Implement the owner's requested executable two-agent test, not another workflow-only plugin. Use the existing stdio MCP without changing relay contracts. Two child endpoint processes own different vault-backed controls, MCP processes and model histories. Their coordinator shares account/address IDs and step numbers only; conversation text crosses the relay, never coordinator IPC. Codex CLI provides real model-generated text within each endpoint; this is not ChatGPT-native subagent dispatch and protocol decisions are deterministic test scaffolding.

The first supported secret provider is an already-authorized 1Password CLI. A new pair uses two generated Password items saved before any registration. Only references and nonsecret identity metadata go into an owner-private state directory. Resolve fresh secrets for recovery and expose them only to the MCP process, never to Codex, output, process arguments or evidence. No fallback vault or plaintext credential export.

Read-only doctor checks Node >=24.19, Codex login, 1Password access and the exact public demo. Init/run require explicit write switches. Run has an exclusive lock and a persistent attempt marker; a partial run is not retried automatically. Preserve checkpoints before writes, fail on changed account IDs, malformed data, incomplete pagination and uncertain outcomes. Never contact the public registry's strangers, publish addresses, unblock contacts, follow redirects, deploy or change main automatically.

Acceptance: two distinct recovered accounts, private addresses, reviewed introduction/recipient acceptance, six correlated messages (three model generations per endpoint), receiver processing/ACK, and matching sender receipts. Evidence is assembled from observed MCP responses plus model invocation events, not claims in generated prose. A synthetic model/relay fixture must never be labeled live acceptance. Failure reports keep missing prerequisites separate from remote outcomes.
