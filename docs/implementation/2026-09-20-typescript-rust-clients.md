# TypeScript SDK and Rust caller: bounded implementation plan

The user approved C# control-plane ownership, TypeScript-first integration, and a Rust independent caller. This increment leaves the C# business logic and existing CLI unchanged. It is based on PR #106 at d500478f60bab9ac607c398a6d8ff4021c439f55; #105/#106 remain prerequisites, not assumed merged.

Implement sdk/typescript with explicit Agent versus operator imports, runtime-checked public JSON, owned request snapshots and bounded HTTP. Implement clients/rust as a small native caller/library for invoke/status/approval, not a rewrite of the product CLI or a second approval engine. Both accept already-issued capability envelopes; neither receives a signing key, mints tokens, generates invocation IDs, computes approval digests or automatically retries. HTTPS is required outside literal loopback. No redirect is followed. Unknown transport delivery remains unconfirmed with the original ID.

The TypeScript runtime needs Node 22+ and no runtime npm dependencies. Rust uses reqwest with explicit no_proxy, no redirect, no retry and request deadlines; the resulting caller needs neither Python nor .NET. Cross-platform release packaging is not established by a Linux test build. A Rust build toolchain and Node are developer/CI prerequisites, not new dependencies of the C# Host.

Acceptance: both clients use shared Unicode/CRLF/null/omission vectors; TypeScript starts and Rust resumes the same approved invocation, then reverse roles. Verify actual Kestrel/Orleans/SQLite/filesystem authority denial, pending/no-attempt, independent TypeScript review/decision, original-caller resume, changed-input conflict, deduplication, owner query, failed admission and unknown completion. Unit transport tests cover redirects, body bounds, cancellation, unconfirmed delivery and runtime-invalid response shapes. Existing Python examples/tests remain optional client examples, not deleted without equivalent evidence.

Local TypeScript regression: 11 passed then two newly added tests failed for runtime workspace coercion and rejection of the existing NotDispatched outcome. Corrected both; 13 passed. Initial missing-module failure before the SDK existed was a setup failure, not claimed behavioral evidence. Rust and .NET require CI in this environment. Exact final commit/results, generated lockfiles and limits will be recorded in the PR. Do not merge, publish npm/crates/binaries, deploy, change real credentials or reset data as part of this implementation.
