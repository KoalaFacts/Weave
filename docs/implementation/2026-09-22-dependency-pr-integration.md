## Why #119 is not an automatic upgrade

Its actual CI build fails with CS9057: the generator references compiler 5.9.0.0,
but the configured SDK's compiler is 5.3.0.0. A successful restore or dependency
scan cannot make that analyzer load. Keep the compatible generator baseline rather
than suppressing the error or expanding this task into an SDK/compiler migration.
The failure and explicit rejection are recorded on #119, not left unattended.

## Resolve the whole lock graph

The original database/AI bot changes updated only directly affected project locks
and included incidental ILLink downgrades. The integration starts from the hardened
main tree and restores the entire solution with its existing global.json policy.
The SDK selector remains 10.0.201 with latestPatch; the preparation run actually
selected 10.0.204. A second locked restore and strict Release build passed.

Twenty-nine affected lockfiles were generated by that restore, not hand-edited.
Their exact before/after bytes, source commit and Git/SHA256 hashes are retained in
preparation artifact 10671499619. Inspection confirmed existing MessagePack,
Microsoft.OpenApi, SSH.NET, SQLite bundle/native library pins and ILLink versions
were preserved. Downstream project edges and resolved dependency versions change
consistently, rather than accepting incomplete per-package lock updates.

A short-lived contents-read preparation job produced the files. A separate
branch-scoped importer checked the exact archive and lock hashes and stored only
allowlisted JSON bytes as immutable Git blobs; it neither checked out nor executed
project code with its write token and did not move refs. Both temporary workflows
are removed from the final tree. Existing CI, dependency evidence producer, audit
policy and warning/format checks remain unchanged.

## Verification and limits

Final acceptance requires the committed full lock graph to pass normal locked
restores, strict build, the complete test suite, formatting, existing security and
plugin checks, plus real base/head dependency comparison. This is a nonempty
package delta, not the earlier zero-change evidence case. Record actual artifacts
and initial failures on the PR; a previous passing run is not final-head evidence.

The updated coverage executable was restored and performed an actual collection
smoke run. This verifies tool execution/output, not code-coverage percentages or
threshold achievement. The new setup action executed successfully in preparation.
The provenance wrapper's declared inputs and immutable dependency were inspected;
no package publishing, release creation, external account or production deployment
was invoked to test it. Existing product tests do not establish live connectivity
to every external database/model service.

No authority, approval, invocation state, transport source, schema or public API
implementation is rewritten here. The known #92 investigation and the remaining
#110 license/permission acceptance keep their existing scope; merging dependencies
does not automatically close either issue. No new plan item, credential rotation,
storage reset, protection bypass or publication is part of this integration.
