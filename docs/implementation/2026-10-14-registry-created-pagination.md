# Anonymous registry browsing in creation order

The public registry continues to load its first page without an account or search. It now presents Browse all / refresh newest, Previous page, a local page number, Next page and explicit Retry page. Every list request asks for at most ten addresses and omits credentials. Back navigation retains only page-start cursors and re-fetches current visibility rather than caching address bodies. Search submission starts a new traversal; editing an unsubmitted search does not alter an existing cursor's query. Empty exact lookup stays local and leaves current browse results intact.

`GET /v1/directory` uses the server-recorded original address `createdAt` descending, then its immutable address ID descending to break timestamp ties. This replaces random UUID ordering. Address edits, public/private changes and republishing do not change original creation time. The response object fields, ten-item limit, owner isolation, public-only/effective/nondeleted filtering, rate limits and exact public lookup are unchanged.

The opaque `afterCursor` now carries the ordering version, query scope, last returned public creation timestamp and address ID. Old ID-only cursors fail with 400; clients restart from the first page rather than silently mixing ordering schemes. Clients should forward the returned cursor verbatim. There is no offset, total-count query, private/global row sequence or new secret in the token. Removing the boundary address does not invalidate the stored tuple or skip older rows. A newly created address above the boundary is seen on refreshing the front rather than shifting forward pages.

This is a live directory, not a frozen snapshot. Privacy, effective-window changes, deletions and newly published older addresses are re-evaluated on each fetch. The page number denotes this browser traversal, not a stable globally numbered page, and arbitrary jump-to-page is not offered. The existing 1000-card bound still applies; this increment does not add an index or claim a larger measured capacity.

Verification: dependency-free tests execute the actual registry script for anonymous load, next/back, query binding/reset, browse all, empty lookup, stale responses and explicit retry. Local SQLite smoke checks execute the actual directory query for ordering/ties and boundary deletion plus insertion. Worker/D1 regressions cover creation ordering, timestamp preservation, privacy changes, malformed/old/query-mismatched cursors. Existing 0/10/11/23-address, rate-limit and browser coverage remains, with deterministic creation-time fixtures and desktop/touch previous-page checks. Full workerd/D1/browser results must be recorded for the actual PR head; local checks alone are not production acceptance.
