# Weave Rust caller

A small independent caller/library for governed tool invocation and scoped outcome
queries. It does not replace the existing `weave` product CLI, add another Agent
runtime, or reimplement C# authority/approval rules. The binary is named
`weave-client` to keep that boundary explicit.

This crate is source-only (`publish = false`); no crate or prebuilt multi-platform
release is published by this increment. CI verifies Linux compilation and real
client behavior. Windows/macOS packaging, static linkage and installer behavior
remain separate verification work. Running the compiled caller needs neither
Python nor .NET; building from source requires the pinned Rust toolchain and the
platform's native build prerequisites.

## Build

From the repository root:

```bash
rustup toolchain install 1.98.1 --profile minimal --component rustfmt --component clippy
cargo +1.98.1 build --locked --manifest-path clients/rust/Cargo.toml
cargo +1.98.1 test --locked --manifest-path clients/rust/Cargo.toml
clients/rust/target/debug/weave-client --help
```

Cargo.lock is generated by Cargo, committed and enforced with --locked. Do not
hand-edit dependency checksums. The HTTP client uses reqwest with rustls and the
platform certificate verifier; do not disable TLS verification to simplify setup.

## Invocation and queries

An administrator must have enabled governed HTTP, connected the intended tool,
and issued a narrow signed capability. Supply its base64url envelope using a
protected `WEAVE_CAPABILITY` environment, not an argument containing credentials.
Environment values still require protection from same-user processes and dumps.

The positional contract is:

```text
weave-client invoke|status|approval URL WORKSPACE TOOL INVOCATION_ID
```

`invoke` reads the exact original invocation JSON from stdin. Its ID and tool must
match the arguments. Retain the nonzero 32-hex ID and original inputs before the
first send; the caller does not generate them or reconstruct a missing body.

```bash
# Use an already retained logical-operation ID, not a new ID for each attempt.
clients/rust/target/debug/weave-client invoke \
  https://weave.example demo files "$INVOCATION_ID" < original-invocation.json

clients/rust/target/debug/weave-client approval \
  https://weave.example demo files "$INVOCATION_ID"

clients/rust/target/debug/weave-client status \
  https://weave.example demo files "$INVOCATION_ID"
```

Replace the example server/context with the actual configured environment. Query
rights are independent of write/read tool grants. Approval decisions are not part
of this Rust caller; use the separately authenticated operator API. After approval,
the original caller may explicitly resubmit its retained request with current
execution authority. The operator must not execute using elevated credentials.

## Do not confuse transport success with operation success

Exit 0 means a validated JSON reply was received. Inspect both its `status` and
`body`, which may describe denied, pending, failed, NotDispatched or OutcomeUnknown.
A successful metadata GET (HTTP 200) can still report an unknown execution outcome.
The Rust library intentionally returns a validated JSON body at this early stage,
not a claim of a complete strongly typed SDK for every future provider.

Exit 2 returns a sanitized error object on stderr. Transport/protocol failures
retain invocationId and `delivery: unconfirmed`; they never authorize an automatic
retry. The program has no retry loop or automatic fresh ID. Output and reviewed
content remain potentially private even though errors do not expose credentials.

Requests use a deadline (default 30000ms, optionally WEAVE_REQUEST_TIMEOUT_MS in
1..300000). This blocking client has no separate asynchronous cancellation API.
Stopping it or timing out does not cancel an already committed effect. A transport
error does not prove the operation was not dispatched. Reconcile through the
original ID, and never retry an unknown effect with a fresh one.

The client disables environment proxies, redirects, retry policy, automatic referer
and idle connection reuse. Only HTTPS or literal loopback HTTP is accepted. Inputs
are limited to 1,048,576 bytes and response reading to 8,388,608 bytes. Critical
response IDs, flags and state enums are validated before returning. These are
transport safeguards, not a sandbox or a guarantee against a compromised server.

`WEAVE_GLOBAL_BEARER` optionally supplies additional Host-level authentication for
trusted environments. Never distribute the Host's shared administrator bearer to
untrusted Agents. Restrict gateway routes and keep administrative access separate;
this caller does not secure unrelated legacy Host endpoints.
